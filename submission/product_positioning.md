# Product Positioning

## 1. Product Name

Recommended bilingual name:

```text
圆周引擎 / Orbit Engine
```

Why:

- `圆周引擎` expresses the product's core loop: recurring field exploration, action, review, and next-cycle continuation.
- `Orbit Engine` is more memorable than the literal `Cycle Engine`, while still implying rhythm, recurrence, and staying in motion around a long-term field.
- It is broad enough to support different fields, not only the user's personal career workflow.

Alternative names:

- Cycle Engine
- Momentum Agent
- Field Orbit Agent

For the 8/16 submission, use:

```text
圆周引擎 / Orbit Engine
```

## 2. One-Sentence Positioning

```text
Orbit Engine is a mobile-first web Agent that helps users build recurring exploration and learning loops in any chosen field, turning scattered signals into structured daily sessions, check-ins, and reusable progress history.
```

Shorter version:

```text
A mobile-first Agent for recurring field exploration and vocational capability building.
```

## 3. Selected GOAI Track And Topic

Track:

```text
Boundless Agents
```

Recommended topic:

```text
AI + Education / Vocational Education
```

Reason:

- The product is about adult learning, technical growth, and long-term capability building.
- It fits the handbook's focus on personalized learning, task decomposition, process guidance, feedback evaluation, learning records, project training, and vocational/programming education.
- It is not a generic chatbot, simple Q&A tool, or content generator.

## 4. Target User

Primary user:

```text
Adult technical professionals who want to build capability in a specific field over time.
```

Examples:

- AI/autonomous-driving engineer tracking world models and 4D reconstruction.
- Robotics researcher following papers and benchmarks.
- Designer building an AI image-generation workflow.
- Product manager exploring a new industry domain.
- Programmer preparing for a new technical direction.

## 5. Core Problem

The problem is not lack of information.

The problem is that long-term exploration breaks down at the execution layer:

```text
Too many signals
  -> hard to decide what matters today
  -> hard to start a focused task
  -> hard to preserve insights
  -> hard to connect daily learning to long-term capability
```

Orbit Engine reduces the activation cost of recurring exploration.

## 6. Product Logic

```text
User defines a field
  -> configures a weekly rhythm
  -> opens today's recommended Agent session
  -> Agent prepares materials or context
  -> user completes a focused task
  -> user checks in
  -> history and feedback inform the next cycle
```

## 7. Core Session Types

### Radar

Purpose:

Discover valuable external signals.

Examples:

- papers
- repos
- product updates
- industry trends
- news
- competitions
- market opportunities

### Deep Dive

Purpose:

Process one selected material deeply.

Examples:

- paper reading
- repo inspection
- article analysis
- course section
- case study
- report reading

### Opportunity Alignment

Purpose:

Align learning with external requirements and opportunities.

Examples by field:

- Career template: JD, recruiter message, resume gap.
- Research template: CFP, benchmark, open problem.
- Creator template: platform trend, user feedback, content opportunity.
- Product template: customer need, competitor movement, market gap.

JD should be treated as one data source under Opportunity Alignment, not as the whole product.

### Weekly Studio

Purpose:

End-of-week workspace for organizing and deciding what to carry forward.

Functions:

- archive
- review
- continue/track/drop judgment
- update ability profile
- adjust next week's rhythm
- optionally update resume or portfolio

## 8. Default Template For Demo

The first demo template:

```text
AI / Autonomous Driving Research Template
```

Example weekly rhythm:

```text
Monday      -> Radar: product / industry signals
Tuesday     -> Radar: technical method signals
Wednesday   -> Opportunity Alignment: JD / market alignment
Thursday    -> Deep Dive: paper select and start
Friday      -> Deep Dive + Weekly Studio: continue, archive, next action
Weekend     -> optional Weekly Studio
```

For the 8/16 demo, implement only the strongest visible loop:

```text
Public paper source
  -> Deep Dive session
  -> Check-in
  -> History
```

## 9. Why It Is Not A Todo App

Todo app:

- user must define all tasks manually
- mainly records completion
- does not understand domain materials
- does not create learning evidence
- does not carry context into the next cycle

Orbit Engine:

- helps discover what is worth doing
- structures each session with field-specific context
- guides a small executable task
- records insight and next action
- preserves history for future cycles

## 10. Submission Positioning

Submission description:

```text
圆周引擎 / Orbit Engine is a mobile-first vocational learning Agent. It helps users explore any chosen field through recurring Agent sessions such as Radar, Deep Dive, Opportunity Alignment, and Weekly Studio.
```
