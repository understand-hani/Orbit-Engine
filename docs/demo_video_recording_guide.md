# Orbit Engine Demo 视频录制指南

最后更新：2026-08-16

适用提交：GOAI 无界应用（Boundless Agents）初赛

## 1. 官方要求结论

根据本地 `docs/Boundless Agents.pdf`、`docs/Agent Infra.pdf` 以及 GOAI 官网当前说明：

- 无界应用初赛必交材料是项目介绍和方案 PPT / PDF。
- Demo 视频或可体验原型属于初赛可选材料，但能增强项目真实性和完成度证明。
- 当前手册和官网没有规定初赛 Demo 视频的固定时长，也未见一镜到底要求。
- Demo 应展示核心功能、典型场景和实际运行效果。
- 项目至少需要证明一条可演示、可验证的完整任务链。
- 不得进行虚假演示或伪造结果；模拟数据需要说明来源和适用边界。

官方页面：

- https://www.goaihz.com/tracks?track=apps
- https://www.goaihz.com/guide

主要评分维度：

| 维度 | 权重 | Demo 中的对应内容 |
| --- | ---: | --- |
| 行业场景价值 | 25% | 技术从业者持续学习和职业能力建设的真实问题 |
| Agent 能力与任务闭环 | 25% | 计划、材料获取、理解、讨论、归档和下一周期 |
| 产品体验与 Demo 完整度 | 20% | 原生 iOS 交互、稳定流程、清晰反馈 |
| 技术实现深度 | 15% | LLM、公开来源、PDF、结构化提取、持久化 |
| 安全、合规与可追溯 | 10% | 来源入口、人工确认、不替代专业判断 |
| 开放与复用价值 | 5% | 可复用 Session、MaterialSource 和归档结构 |

## 2. 成片建议

推荐成片时长：

```text
2 分 20 秒至 2 分 40 秒
```

推荐形式：

- iPhone 原生竖屏录制。
- 分模块录制，后期拼接。
- 剪辑完成后统一录旁白，不在操作时实时解说。
- 使用简短字幕标明流程节点和被剪除的等待时间。
- 主线占绝大部分时间，其他模块只作为能力扩展快速展示。

核心叙事：

```text
方向与计划
  -> Signal Radar
  -> Deep Dive
  -> Agent 讨论
  -> 结构化归档
  -> Weekly Studio
  -> 下一周期
```

视频不能拍成多个静态页面的平均巡览。Deep Dive、Agent 讨论和归档闭环应占成片约一半时间。

## 3. 推荐镜头表

| 时间 | 操作与画面 | 需要证明的能力 |
| --- | --- | --- |
| 0:00-0:08 | iPhone 桌面展示 Orbit Engine 图标，点击进入 Today | 产品真实存在，是原生 App |
| 0:08-0:22 | 展示计划上下文、Scheduled 和今日工作区 | Agent 根据长期方向组织每日任务 |
| 0:22-0:40 | Signal Radar 输入主题、点击生成、展示信号判断和来源 | 外部信号获取、工具调用和价值判断 |
| 0:40-1:22 | Deep Dive 展示论文卡片、Abstract、阅读章节、关键图和 Agent 分析 | 材料理解、证据提取和结构化阅读 |
| 1:22-1:42 | 与 Agent 讨论，保存到归档，展示讨论总结、关键洞察和行动项 | 多轮交互、提炼和结构化记忆 |
| 1:42-1:55 | Opportunity Alignment 展示岗位分析、能力差距或推荐行动 | 学习证据与外部机会对齐 |
| 1:55-2:18 | Weekly Studio 展示本周总结、下周优先级和同步计划 | 跨模块汇总并形成下一周期 |
| 2:18-2:32 | 归档页展示新生成的论文、讨论或行动记录 | 结果持久化和可追溯闭环 |
| 2:32-2:40 | 回到 Today 或品牌画面，显示结束字幕 | 收束产品价值 |

如果最终需要压缩到 90 秒，优先删除 Opportunity Alignment，并缩短 Signal Radar；不要删除 Deep Dive 到归档的完整链路。

## 4. 各镜头具体操作

### 4.1 开场与 Today

1. 从 iPhone 桌面开始，保持 Orbit Engine 图标可见 1 秒。
2. 点击图标进入 App。
3. 展示当前专业方向、计划周期和今天的 Scheduled Session。
4. 点击进入今日工作区。

旁白重点：

```text
Orbit Engine 面向需要长期建设专业能力的技术从业者，
把分散信号组织成每天可执行、可积累的 Agent Session。
```

### 4.2 Signal Radar

1. 展示本轮输入主题或来源。
2. 点击生成 Signal Radar。
3. 加载状态保留 1 至 2 秒。
4. 展示一个最强信号的标题、来源、证据状态和 Agent 判断。
5. 展示继续跟踪、转入 Deep Dive 或暂存等路由动作。

不要逐条滚动所有新闻。评委只需要看到 Agent 不只是聚合内容，还在判断证据和下一步。

### 4.3 Deep Dive

1. 展示主论文和候选材料，打开主论文。
2. 快速展示标题、作者、来源和原始 Abstract。
3. 展示 Agent 自动读取后的阅读章节和精选段落。
4. 打开一张关键图，停留在纯图画面约 2 秒。
5. 向下展示与该图直接对应的 Agent 分析和阅读问题。

这是整条视频最重要的部分，需要清楚表现：

```text
真实材料 -> 原始证据 -> Agent 提取 -> 用户可执行的理解任务
```

### 4.4 Agent 讨论与归档

1. 针对当前论文或关键图提出一个具体问题。
2. 展示 Agent 的具体回答，不使用泛化问题。
3. 点击“保存讨论到归档”。
4. 等待“Agent 正在提炼讨论精髓”。
5. 展示讨论总结、关键洞察和行动项。
6. 确认三项内容与本轮对话和材料直接相关后保存。

推荐问题：

```text
这张图能够证明方法在长序列中的时序一致性吗？证据还缺什么？
```

### 4.5 Opportunity Alignment

只展示一个短链路：岗位要求或机会输入，Agent 识别技术重合、能力差距，并形成候选行动。

该模块用于证明 Orbit Engine 不只读论文，还能把学习结果与现实机会对齐。不要在此展开完整编辑流程。

### 4.6 Weekly Studio 与归档

1. Weekly Studio 展示已完成归档数量。
2. 点击生成，加载状态保留 1 至 2 秒。
3. 展示本周具体总结和下周优先顺序。
4. 点击同步下一步到计划。
5. 打开归档页，展示刚才形成的新记录。

结束旁白：

```text
Orbit Engine 不是一次性问答工具。
它把信号、材料、讨论和行动沉淀为可追溯记录，并驱动下一周期。
```

## 5. 分段录制文件

每段开始前静止 1 秒，操作结束后再静止 1 秒，便于剪辑。

```text
01_icon_today.mov
02_radar_input.mov
03_radar_result.mov
04_deepdive_paper.mov
05_key_figure.mov
06_agent_discussion.mov
07_archive_card.mov
08_opportunity.mov
09_weekly_studio.mov
10_history.mov
```

每个 LLM 模块可以单独录制多次，选择内容和响应最稳定的一次。同一镜头中的输入与输出必须来自同一次请求。

## 6. LLM 等待与后期剪辑

允许的处理：

- 删除 LLM 请求中间的大部分等待时间。
- 保留点击生成和 1 至 2 秒加载反馈，再切到同一次请求的结果。
- 在画面角落短暂标注“生成等待已剪除”。
- 普通滚动和较长页面浏览可加速到 1.5 至 2 倍。
- 极长等待片段最多可加速到 4 倍，但直接剪除通常更清晰。
- 可以去除误触、无意义停顿和重复滚动。

不能采用的处理：

- 把一次输入与另一次请求的结果伪装成同一次运行。
- 用后期字幕虚构 App 实际没有生成的字段或能力。
- 把 mock 数据冒充实时外部数据。
- 隐藏会改变产品结论的错误或失败结果。

评委关注的是输入、处理逻辑和结果是否真实对应，不需要观看完整网络等待过程。

## 7. 旁白与字幕

推荐先完成画面剪辑，再按最终节奏录中文旁白。

字幕只承担三类信息：

- 当前步骤，例如“Signal Radar：筛选高价值信号”。
- Agent 行为，例如“读取原文并提取证据”。
- 剪辑说明，例如“生成等待已剪除”。

不要用字幕反复解释界面上已经存在的文字。背景音乐应关闭或保持很低，旁白必须清晰。

## 8. 当前项目录制状态

截至 2026-08-16：

- 原生 iOS App 是主展示面。
- Signal Radar、Deep Dive、Agent 讨论、Opportunity Alignment、Weekly Studio 和归档均已有可展示界面。
- 论文详情显示原始 Abstract。
- 关键图详情显示裁出的图片及对应 Agent 分析。
- 讨论归档会生成讨论总结、关键洞察和行动项。
- App Icon 已更新为最终 Orbit Engine 版本。
- 本地数据库中的 completed 归档记录已经清空，录制时可从空状态生成新记录。
- 本地数据库中的 Demo User 已删除，首次加载会显示空白“新用户”。
- 当前后端进程和 Cloudflare 隧道未运行，录制前必须重新启动并验证。

注意：如果录制 Weekly Studio，需要先在同一录制数据库中完成至少一条真实归档，否则周总结缺少有效输入。

## 9. 录制前准备

1. 启动 FastAPI 后端和 Cloudflare 隧道。
2. 确认 iOS App 使用的后端地址与当前隧道一致。
3. 在 App 内测试 Today、Radar、Deep Dive、讨论归档和 Weekly Studio。
4. 使用同一个研究方向和同一篇论文贯穿主要镜头。
5. 开启 iPhone 勿扰模式，关闭消息和来电通知预览。
6. 清理状态栏中的个人热点、定位或其他不必要标识。
7. 不展示 API Key、终端窗口、调试日志和临时隧道地址。
8. 确认 PDF、关键图和来源链接可以正常打开。
9. 确认归档初始为空，再录制从讨论到新增记录的过程。
10. 先完整演练一次，再正式分段录制。

## 10. 导出与提交

推荐导出参数：

```text
封装：MP4
编码：H.264
分辨率：1080 x 1920
帧率：30 fps
视频码率：8-12 Mbps
音频：AAC，48 kHz
```

提交前检查：

- 成片不超过约 3 分钟。
- 开头 10 秒内出现产品和真实 App。
- 至少展示一条完整任务链，而非静态页面集合。
- 所有文字在手机画面中清晰可读。
- 没有通知、个人信息、密钥或调试信息。
- 输入、输出和归档内容前后一致。
- 模拟数据已明确标注，真实来源可追溯。
- 视频链接无需登录即可播放。
- 使用无痕窗口测试视频链接和音频。
- 视频叙事与项目介绍、PPT 和仓库说明一致。

## 11. 最低可交付版本

如果时间不足，只录以下 90 秒主链路：

```text
App Icon / Today
  -> Deep Dive 论文
  -> Abstract / 关键图 / Agent 分析
  -> Agent 讨论
  -> 保存讨论到归档
  -> 归档页出现新记录
```

该版本仍然覆盖真实输入、Agent 处理、结构化结果、用户确认和持久化验证，是比功能合集更有效的最低可交付 Demo。
