# GOAI 产品重定义 v1

日期：2026-10-29
分支：`agent-research-v1`

## 1. 为什么要收缩

当前产品的问题不是缺少 Radar、Deep Dive、Weekly Studio 等能力，而是它们
将“发现信息、理解信息、决定行动、保存判断”拆成了过多入口。自动全网 Radar
还依赖不稳定的检索服务，导致每日使用的第一步经常失败。

新的判断是：产品必须先成为用户每天愿意打开的个人研究工具；求职作品价值来自
真实使用后的 Agent 判断、数据与评估，而不是功能数量。

## 2. 新定位

> 面向技术研究与职业转型的个人 Research Signal & Action Agent。
> 它把可信来源的信息转化为与个人主线相关的少量行动，并保留可追溯的判断和进度证据。

用户是当前唯一的真实用户。系统不以多用户、商业化或完整生产效率工具为目标。

## 3. 最小闭环

```text
可信技术信号
  -> 判断是否和当前主线有关
  -> 生成少量当日行动
  -> 逐条打卡
  -> 自动归档为研究与能力证据
```

## 4. 信息架构

```text
首页
  -> 今日行动（最多 3 条，逐条打卡）
  -> 今日信号（可信来源输入）
  -> 快速添加链接

信号详情
  -> 原文与证据状态
  -> Agent 解读与讨论
  -> 忽略 / 追踪 / 转为今日行动

机会判断
  -> JD、招聘信息、技术方向选择

我的轨迹
  -> 日归档、被保留材料、关键判断、可选周摘要
```

## 5. 模块取舍

### 今日信号（本轮优先实现）

- 原 Radar 改为 Signal Inbox；不再把自动全网扫描作为主链路。
- 第一版的可靠输入是用户粘贴的公众号文章、论文、GitHub、官方发布页等公开链接。
- 每条 Signal 必须保留原始 URL、来源、正文证据状态、与当前研究计划的关系，以及建议动作。
- 后端可尝试提取公开页面段落；被反爬、验证码或访问限制阻断时，必须保留链接并明确“未取得正文”，不能编造解读。
- 公众号账号主页的自动日更发现属于后续实验，不可成为每日流程的前提。

### 解读与继续研究

- 取消独立 Deep Dive 产品流程与重投入 PDF 阅读器路线。
- 用户在同一条 Signal 中阅读、提问、记录判断并决定忽略、追踪或继续行动。
- 后台保留 `Signal` 与被保留的 `Material / Tracked Item` 区分，避免系统退化为普通阅读器。

### 每日行动与打卡（下一阶段）

- 每日自动生成最多 3 条、10/20/30 分钟的行动。
- 任务只来自：未完成但仍值得继续的行动、当日高相关 Signal、当前研究主线的下一步。
- 用户可完成、跳过、延后或转为追踪；完成时记录做了什么、关键发现、继续/追踪/放弃与下一步。

### 自动归档（下一阶段）

- 将每日目标、行动状态、关联 Signal、用户洞察、Agent 提炼判断和下一步自动写入轨迹。
- 周度内容仅为可选的短摘要，不保留独立 Weekly Studio 工作台。

### Opportunity Alignment

- 保留为低频、事件驱动入口，用于 JD、招聘联系和方向选择。
- 继续识别 TPM 风险、技术匹配、能力缺口和时机；不推动当前窗口内的立即投递。

## 6. 明确暂停或删除

- 独立 Radar / Deep Dive 两套用户流程。
- PDF 段落标注、关键图抽取与阅读器产品化。
- 强制 Weekly Studio 与多层任务管理。
- 以不稳定网页搜索或公众号爬取作为唯一信息来源。
- 多用户、商业化、社区与泛生产力功能。

## 7. 后端收敛方向

长期核心实体收敛为：

```text
Source -> Signal -> Action -> DailyCheckin -> ArchiveEntry
                              \
                               -> Opportunity
```

最关键的 Agent 逻辑是：

```text
个人主线 + 未完成行动 + 新 Signal + 时间预算
  -> 当天最多 3 条行动
  -> 完成 / 跳过 / 追踪反馈
  -> 更新下一天的选择
```

## 8. 当前阶段验收

先完成可信链接输入后，连续两周、每周至少 3 天真实使用，再判断它是否比
“公众号收藏 + 备忘录”更容易启动、更能形成技术判断。若不能，应继续收缩而非加功能。
