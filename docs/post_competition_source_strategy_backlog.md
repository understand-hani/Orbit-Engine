# 初赛后：材料源偏好与 Deep Dive 检索策略升级

## 当前初赛策略

为保证 Demo 稳定，Deep Dive 暂时采用 arXiv-only 内容合同：

- 优先调用 arXiv API；
- arXiv API 不可访问时，可通过博查检索，但只接收 `arxiv.org/abs/...` 论文详情页；
- 拒绝期刊主页、Call for Papers、新闻、普通网页和 GitHub 仓库；
- 未找到合格论文时明确返回空结果，不用弱相关网页凑数；
- 未获取论文正文时，只展示真实摘要，不伪造段落、图片或实验结论。

## 初赛后需要补齐

### 1. 把“允许的来源”升级为有优先级的检索策略

目前 `source_preferences` 是无序多选，无法表达“arXiv 优先、官方文档其次、网页仅兜底”。建议增加：

- `primary_sources`：首选来源及顺序；
- `fallback_sources`：允许回退的来源及顺序；
- `excluded_sources`：明确禁止的来源；
- `content_types`：论文、官方技术文档、产品发布、代码仓库、行业报告等；
- `freshness`：最新优先、经典材料优先或混合；
- `evidence_level`：是否必须有全文、摘要、作者、日期、PDF 或官方出处。

需要兼容现有 `source_preferences` 数据，不能让旧用户配置失效。

### 2. 方向配置提供 Agent 推荐和用户确认

在“我的 → 方向配置 → Agent 检索策略”中：

- Agent 根据领域和当前阶段推荐默认来源优先级；
- 用户可以调整顺序，而不只是勾选；
- 显示每种来源适合什么任务以及回退影响；
- 保存前预览最终检索策略；
- 应用设置中的“领域偏好”展示同一份配置，不维护第二份副本。

示例默认策略：

- 研究/算法方向：arXiv → 官方论文页/项目页 → GitHub；
- 软件工程方向：官方文档 → GitHub → 技术博客；
- 产品/行业方向：企业官网/官方发布 → 研究机构 → 可信新闻；
- 政策/法规方向：政府/监管机构 → 官方解释 → 可信媒体。

### 3. Deep Dive 真正消费检索策略

- 查询规划必须读取目标、全周期计划、本周重点、当前任务、跟踪关键词和来源优先级；
- 每个数据源使用独立适配器和内容类型校验，不能把网页统一包装成 Paper；
- 候选先做硬类型过滤，再做与目标/计划的相关度评分；
- 主材料必须满足 Deep Dive 的最低证据条件；
- 候选材料应承担补充、对照或反例角色，不能只是第二个搜索结果；
- 保存检索依据、命中关键词、来源类型和淘汰原因，方便解释推荐。

### 4. 内容抓取与阅读能力

- arXiv：metadata、PDF 下载、正文解析、章节/页码定位、图表提取；
- 官方文档：正文抽取、版本和更新时间识别；
- GitHub：README、release、活跃度和许可证；
- 网页：正文抽取、发布主体、发布时间和转载识别；
- 所有来源都要区分“原文证据”和“Agent 总结”，禁止用摘要冒充全文。

### 5. 质量、失败和测试

- 为期刊主页、CFP、新闻、聚合页和搜索结果页建立拒绝测试；
- 为不同领域建立来源优先级测试；
- 为来源不可用、超时、零结果和旧配置迁移建立测试；
- UI 明确显示使用了哪个来源策略、为什么回退以及材料证据状态；
- 记录检索耗时和各阶段失败原因，避免只显示“生成失败”。

## 完成标准

- 用户配置的来源优先级能端到端影响 Deep Dive 候选；
- 候选的真实内容类型与 UI 标签一致；
- 同一方向在固定测试数据下得到稳定、可解释的主材料和候选材料；
- 任何回退都不能突破用户明确禁止的来源类型；
- 没有合格材料时返回空状态，不生成 mock 或用无关网页补位。
